# Eval: live generator vs verified seeds

`npm run eval` compares each first-pass guide from the live generator (`verification/raw/<slug>.vN.json`) with the verified seed guide (`data/guides/<slug>.json`). It checks the fields a developer acts on, using the rules in docs/VERIFICATION.md. The table between the markers is generated; the rest is written by hand.

## What the numbers say (prompt v1, 7 apps)

- **Tier:** exact for 5 of 7, within one tier for all 7. Both misses were too easy (Microsoft 2 vs 3, LinkedIn 2 vs 3), the expensive direction for a developer planning a launch.
- **Composio managed app status** matched for all 7, because it comes from a deterministic tool, not the model.
- **Customer-side gate** matched for 5 of 7.
- **Stage-level review and wait ranges** matched for about two thirds of stages. The scope review-level match uses keyword matching between differently named scope tiers, so read it as a rough signal.
- **The bigger gap is coverage, not tier.** v1 guides had 7 to 11 evidence items, against 28 to 49 in the seeds. They missed four facts that change an agent builder's plan (listed in docs/LESSONS.md): Google test users' 7-day access expiry, Meta's 30-day API-call prerequisite, Microsoft tenant consent defaults, and LinkedIn closing `r_member_social`.

Seven apps is a small sample. One app more or less moves every percentage a lot, and the seeds were written by a research agent and checked by a second agent, not by a person. So this shows the direction of the errors, not an accuracy rate.

## What changed because of it

Prompt v2 (docs/LESSONS.md) adds a short list of agent-critical checks, requires a recent-changes search and at least 5 opened pages, and adds rules against rounding numbers up and silently picking between conflicting pages. Three fixes went into code instead of the prompt, so they hold on every run: probe evidence is recorded automatically, uncited pages are downgraded, and the portal probe wording changed.

## v2 results

Not measured yet. The API account ran out of credits before the v2 re-runs. Run `bash scripts/live-tests.sh` (it re-runs Microsoft and LinkedIn, the two v1 misses) and the table below gains a "Prompt v2" section. What I would look for: whether both reach tier 3, and whether the four missing facts now appear. If they do not, the next step is a second research pass that only answers the agent-critical checks, rather than a longer prompt.
