# Eval: live generator vs verified seeds

`npm run eval` compares each first-pass guide from the live generator (`verification/raw/<slug>.vN.json`) with the verified seed guide (`data/guides/<slug>.json`). It checks the fields a developer acts on, using the rules in docs/VERIFICATION.md. The table between the markers is generated; the rest is written by hand.

## What the numbers say (prompt v1, 7 apps)

- **Tier:** exact for 5 of 7, within one tier for all 7. Both misses were too easy (Microsoft 2 vs 3, LinkedIn 2 vs 3), the expensive direction for a developer planning a launch.
- **Composio managed app status** matched for all 7, because it comes from a deterministic tool, not the model.
- **Customer-side gate** matched for 5 of 7.
- **Stage-level review and wait ranges** matched for about two thirds of stages. The scope review-level match uses keyword matching between differently named scope tiers, so read it as a rough signal.
- **The bigger gap is coverage, not tier.** v1 guides had 7 to 11 evidence items, against 28 to 49 in the seeds. They missed four facts that change an agent builder's plan (listed in docs/LESSONS.md): Google test users' 7-day access expiry, Meta's 30-day API-call prerequisite, Microsoft tenant consent defaults, and LinkedIn closing `r_member_social`.

Seven apps is a small sample. One app more or less moves every percentage a lot, and the seeds were written by a research agent and checked by a second agent, not by a person. So this shows the direction of the errors, not an accuracy rate.

## What changed because of it

Prompt v2 (docs/LESSONS.md) adds a short list of agent-critical checks, requires a recent-changes search and at least 5 opened pages, and adds rules against rounding numbers up and silently picking between conflicting pages. Three fixes went into code instead of the prompt, so they hold on every run: probe evidence is recorded automatically, uncited pages are downgraded, and the portal probe wording changed.

## v2 results (2 apps, the two v1 misses)

v2 did not fix the tier misses.
- **Microsoft: still tier 2 (seed 3).** v2 now says tenants that restrict consent will block an unverified app, and it puts publisher verification in the next step. But it treats the restriction as something some tenants choose, not as the current default for mail and calendar scopes.
- **LinkedIn: tier 5 (seed 3), an overshoot.** v2 found the right facts (Community Management API review, refresh tokens only for approved partners). It then tagged refresh tokens as partner only, so the "act while offline" tier became the verdict.

**The lesson repeated.** Both v2 runs made only 1 web search, though the v2 prompt asks for at least two, one about recent changes. A rule in the prompt was not followed. That is lesson 12 again: rules that matter need code.

**Experiment: enforce the research minimum in code ("v3" below).** I added a check in the agent loop. A `submit_guide` call that arrived before 2 searches and 5 opened pages was sent back once with the counts. I re-ran Microsoft and LinkedIn.
- It worked as a mechanism. Both runs were sent back once, then made 2 searches and opened 5 to 6 pages.
- It did not change the result. Microsoft stayed at tier 2 and still did not find the tenant consent default. LinkedIn stayed at tier 5 and still did not mention that `r_member_social` is closed.
- It made runs slower: 112s and 127s instead of about 60s, because the model writes the whole guide twice.

So I reverted it. The shipped code is prompt v2 with no gate. The two misses are judgment errors about these providers, and more searching did not fix them.

**What I would do next.** The verified seeds already carry the right answers, so the library is the fix for popular apps. For live guides, the step that caught these errors was the independent verifier, not more research. I would run a short verifier pass on the tier-deciding claims of each live guide, about 30 more seconds, and show its verdict on the page. Separately, the verdict tier should come from the use case most agents need (read + write), not from the hardest scope tier. LinkedIn shows why: one partner-only feature made the whole verdict tier 5.
